# Генерация кода / исполнение

## Архитектура бэкенда

Финальная фаза имеет два независимых пути:

1. **LLVM IR + clang (по умолчанию).** Компилятор печатает текстовый LLVM IR
   из своего трёхадресного IR и зовёт `clang-22` для сборки нативного
   исполняемого файла. Линкуется с C-runtime'ом (`src/codegen/runtime.c`).
2. **Интерпретатор IR (`--interp`, fallback).** Регистровая виртуальная
   машина исполняет тот же трёхадресный IR напрямую, без генерации нативного
   кода. Гарантированно работает в любой среде, не зависит от clang.

```
Исходник (.herta)
   → [Лексер]      → токены
   → [Парсер]      → AST
   → [Семантика]   → аннотированный AST
   → [Lowering]    → IR (трёхадресный код)         ← herta.ir
   →   ┌─ [LLVM emitter] → .ll → clang → бинарь    ← herta.llvm  (по умолчанию)
       └─ [Интерпретатор]                          ← herta.interp (--interp)
```

Промежуточное представление между фронтендом и бэкендом — общее: оба пути
читают одинаковые `ir::Module`-объекты. Это значит, что фронтенд (лексер,
парсер, семантика, lowering, оптимизации) обслуживает оба пути без изменений.

## Путь LLVM (по умолчанию)

### Модуль эмиттера

[`src/codegen/llvm_emit.cppm`](../src/codegen/llvm_emit.cppm) принимает
`std::vector<ir::Module>` и возвращает строку с текстовым LLVM IR (`.ll`).

### Сборка бинаря

`myc` пишет `.ll` во временный файл и вызывает:

```
clang-22 -O1 prog.ll src/codegen/runtime.c -o <out>
```

`-O1` важен: clang проводит `mem2reg`, устраняя альлоки, которые эмиттер
ставит вместо честной SSA-формы (см. ниже). Без `-O1` код тоже работает, но
сильно медленнее.

### Соглашение о вызовах

System V AMD64 ABI (то, что использует clang на Linux/x86-64). Это даёт
бесплатный интероп с C-runtime'ом: `printf`, `getline`, `malloc` — всё через
обычные сишные сигнатуры.

### Представление типов Herta в LLVM IR

| Herta              | LLVM IR                                |
|--------------------|----------------------------------------|
| `int8..int64`      | `i8 / i16 / i32 / i64`                 |
| `uint8..uint64`    | `i8 / i16 / i32 / i64` (signedness — на операторах) |
| `float32`          | `float`                                |
| `float64`          | `double`                               |
| `bool`             | `i1`                                   |
| `char`             | `i32` (Unicode codepoint)              |
| `string`           | `%struct.herta_string = type { i64, ptr }` (по значению) |
| `[T; N]`           | `[N x <T>]` (по значению, копируется при присваивании) |
| `struct S {…}`     | `%struct.S = type { … }` (по значению) |
| `void` / `unit`    | `void`                                 |

Знаковость отделена от типа: для int используется `sdiv/srem/sext/sgt/…`,
для uint — `udiv/urem/zext/ugt/…`. LLVM-тип у них одинаковый, поэтому
бит-идентичные приведения `int32 ↔ uint32` не порождают инструкций.

### Memory form

Каждая `Var` и каждый `Temp` IR'а получает alloca'у на входе функции
(prolog). Чтение операнда — `load`, запись — `store`. Это даёт два эффекта:

- **Естественная value-семантика.** Загрузка `%struct.X*` через `load`
  возвращает first-class aggregate; запись обратно в другую alloca'у
  копирует значение целиком.
- **Простота эмиссии.** Не нужно вести phi-узлы вручную; clang в `-O1`
  пропускает `mem2reg`, и в финальном бинаре аллок не остаётся.

### Неявное widening

IR не несёт явных `Cast` для widening (semantics.md §6.2). Эмиттер вычисляет
общий числовой тип для каждой бинарной операции/сравнения и вставляет
`sext` / `zext` / `sitofp` в точке использования.

### Runtime-проверки

Целочисленное `/` и `%`: компилятор вставляет проверку и переход на
`@herta_rt_div_zero(i64 line)`, который пишет `runtime error: division by
zero at line <N>` в stderr и завершается с кодом `1`.

Индексирование массива: проверка `idx < 0 || idx >= N` → `@herta_rt_oob`,
сообщение `runtime error: index out of bounds: <i>, size <M> at line <N>`.

`assert(false)` → `@herta_assert_fail(line)` → `assertion failed at line <N>`.
`panic(msg)` → `panic: <msg>`. `exit(code)` → `std::exit(code)`.

### C-runtime

[`src/codegen/runtime.c`](../src/codegen/runtime.c) экспортирует:

- `herta_print_int/uint/float/bool/char/string` — вывод + `\n`.
- `herta_string_len`, `herta_string_concat`, `herta_string_eq`,
  `herta_input` — операции над строками.
- `herta_exit`, `herta_panic`, `herta_assert_fail`, `herta_rt_div_zero`,
  `herta_rt_oob` — терминаторы исполнения.

Память для строковых буферов (конкатенация, `input`) — malloc без free
(арена-модель, semantics.md §5). Учебной программе хватает.

### Имена функций и кросс-модульные вызовы

Все функции получают имя `@<Module>.<flat>`, кроме `main` (`@main`).
Внутри модуля callsite использует канонически-полное имя той же функции.
Кросс-модульные `Module.fn` уже включают префикс модуля и резолвятся в
эмиттере через map'у модулей.

### Псевдонимы типов

`type Alias = Target;` — синонимы, не отдельные типы (semantics.md §10).
Перед эмиссией собирается плоская таблица алиасов из всех модулей; типы
во всех инструкциях IR раскрываются рекурсивно (включая элементы массивов).

## Путь интерпретации (`--interp`)

Регистровая виртуальная машина, исполняющая тот же трёхадресный IR.
Используется как fallback и для тестов (детерминированный, не зависит от
clang). Подробности см. в [`src/codegen/interp.cppm`](../src/codegen/interp.cppm)
и сводно ниже.

### Модель ВМ

- Кадр (Frame): два хранилища — `vars` (имя→значение) и `temps` (id→значение).
- Поток управления: pc + карта `label → индекс` инструкции; `Goto`, `Branch`,
  `Return` ведут себя как в IR.
- Builtin'ы и runtime-ошибки — те же сообщения и коды, что у LLVM-пути.

### Модель значений

`std::variant` со всеми герта-типами по значению (массивы — `vector<Value>`,
структуры — `map<string,Value>`). Копирование при присваивании реализует
value-семантику естественно.

## Точка входа CLI

```
myc <source.herta> [options]
```

| Флаг              | Действие                                              |
|-------------------|-------------------------------------------------------|
| (без флагов)      | компиляция в нативный бинарь через LLVM + clang       |
| `-o <path>`       | путь выходного бинаря                                 |
| `--run`           | скомпилировать, запустить, вернуть код процесса       |
| `--interp`        | путь интерпретации (без бинаря, исполнение в проце)   |
| `--emit-llvm`     | вывести `.ll` в stdout и выйти                        |
| `--dump-tokens`   | поток токенов                                         |
| `--dump-ast`      | AST                                                   |
| `--dump-ir`       | трёхадресный IR (после оптимизаций, если не `--no-opt`) |
| `--no-opt`        | отключить оптимизации IR (constant folding + DCE)     |
