# semantics.md — Семантика языка Herta

---

## 1. Стратегия вычисления

Язык использует **call-by-value**: при вызове функции все аргументы вычисляются
полностью до передачи в функцию, и в параметр копируется значение, а не ссылка.

```
fn double(x: int32) int32 {
    x = x * 2;   // изменение параметра не влияет на вызывающую сторону
    return x;
}

fn main() int32 {
    var a: int32 = 5;
    let b := double(a);
    // a == 5, b == 10
    return 0;
}
```

Порядок вычисления аргументов при вызове функции — **слева направо**.

---

## 2. Семантика присваивания (value semantics)

Все значения передаются и присваиваются **по значению** — копированием.
Это касается структур и массивов: присваивание создаёт независимую копию.

```
struct Point { x: int32, y: int32, }

fn main() int32 {
    let p1: Point = Point { x: 1, y: 2 };
    var p2: Point = p1;   // независимая копия
    p2.x = 99;
    // p1.x == 1, p2.x == 99
    return 0;
}
```

---

## 3. Мутабельность переменных

Язык различает два вида объявлений:

| Ключевое слово | Мутабельность | Поведение |
|---|---|---|
| `let` | иммутабельная | повторное присваивание запрещено |
| `var` | мутабельная | значение можно изменить через `=` |

Попытка присвоить новое значение `let`-переменной является **ошибкой компиляции**.

```
let x: int32 = 10;
x = 20;   // ОШИБКА: x объявлена как let

var y: int32 = 10;
y = 20;   // OK
```

Мутабельность относится к **переменной**, а не к значению. Если переменная — структура,
объявленная через `let`, то изменить её поле тоже нельзя.

```
let p: Point = Point { x: 1, y: 2 };
p.x = 5;   // ОШИБКА: p объявлена как let
```

---

## 4. Инициализация переменных

Каждая переменная **обязана** быть инициализирована в момент объявления.
Использование переменной без инициализации является **ошибкой компиляции**.

```
var x: int32;        // ОШИБКА: нет начального значения
var y: int32 = 0;   // OK
```

Объявление с выводом типа (`:=`) всегда содержит инициализатор по синтаксису,
поэтому дополнительных проверок не требует.

## 5. Время жизни и область видимости

Переменная существует **в пределах блока**, в котором объявлена — с момента
объявления до закрывающей фигурной скобки `}` этого блока.

```
fn main() int32 {
    var x: int32 = 1;
    {
        var y: int32 = 2;
        // x и y видны здесь
    }
    // y недоступна здесь — ОШИБКА
    return x;
}
```

### Shadowing

Внутреннее объявление с тем же именем **скрывает** внешнее в своей области видимости.
Внешняя переменная при этом не уничтожается и остаётся доступной после выхода из блока.

```
var x: int32 = 1;
{
    var x: int32 = 2;   // скрывает внешний x
    print(x);           // выводит 2
}
print(x);               // выводит 1
```

### Запрет повторного объявления

Объявить два идентификатора с одинаковым именем **в одной области видимости** запрещено.

```
var x: int32 = 1;
var x: int32 = 2;   // ОШИБКА: x уже объявлен в этой области
```

### Запрет использования до объявления

Использование идентификатора **до** его объявления в той же или охватывающей
области видимости запрещено.

```
print(x);            // ОШИБКА: x ещё не объявлен
var x: int32 = 5;
```

## 6. Система типов

### 6.1 Номинальная типизация

Два типа совместимы, только если их **имена совпадают**.
Структурное сходство не является основанием для совместимости.

```
struct A { x: int32, }
struct B { x: int32, }

var a: A = A { x: 1 };
var b: B = a;   // ОШИБКА: A и B — разные типы
```

### 6.2 Неявные приведения (только расширяющие)

Язык допускает **ограниченный** набор неявных приведений — только **расширяющих**
(widening). Любое сужающее или семантически опасное преобразование требует
явного cast'а `T(expr)`.

Подробные правила см. в [types.md §5.4](types.md#54-неявные-приведения). Кратко:

- `intN` → `intM` при `M > N` (расширение знака)
- `uintN` → `uintM` при `M > N` (расширение нулём)
- `uintN` → `intM` при `M > N` (всегда помещается)
- `intN` / `uintN` → `float64` (для всех N; возможна потеря точности для 64-битных)
- `intN` / `uintN` → `float32` для N ≤ 16
- `float32` → `float64`
- Числовые литералы — «нетипизированные» и адаптируются к контексту,
  если значение помещается в целевой тип (см. §6.4).

```
var x: int32 = 5;
var y: float64 = x;           // OK: int32 → float64 (widening)
var z: int8   = x;            // ОШИБКА: сужающее приведение требует cast
var w: int8   = int8(x);      // OK
var b: bool   = 1;            // ОШИБКА: bool ↔ число запрещены даже явно
```

### 6.3 Правила приведения типов

Допустимые явные приведения:

| Из            | В                        | Поведение |
|---------------|--------------------------|-----------|
| `intN`        | `intM`, `uintM`          | расширяющее (widening) или сужающее (narrowing) |
| `uintN`       | `intM`, `uintM`          | расширяющее или сужающее |
| `intN`/`uintN`| `float32`, `float64`     | преобразование в вещественное |
| `float32`     | `float64`                | расширяющее |
| `float64`     | `float32`                | сужающее, возможна потеря точности |
| `floatN`      | `intN`/`uintN`           | усечение дробной части |

Приведение между несовместимыми типами (например, `string` → `int32`) является
**ошибкой компиляции**.

### 6.4 Переполнение

При сужающем приведении или арифметическом переполнении целых чисел
происходит **усечение по разрядности** (wraparound). Поведение определено
и не считается ошибкой времени выполнения.

```
var x: int8 = int8(300);   // 300 % 256 = 44
```

### 6.5 Синонимы типов (type alias)

Синоним — это **альтернативное имя** для существующего типа, а не новый тип.
Значения синонима и базового типа совместимы без приведения.

```
type Meters = int32;

var m: Meters = 5;
var n: int32 = m;   // OK — Meters и int32 — один и тот же тип
```

## 7. Семантика выражений

### 7.1 Арифметические операции

Применимы к числовым типам (`intN`, `uintN`, `floatN`).

Если операнды разных типов, применяется **неявное widening** одного из них
к типу другого по правилам §6.2 (см. также [types.md §5.4](types.md#54-неявные-приведения)).
Если ни одно из направлений widening не допустимо — **ошибка компиляции**,
требуется явный cast.

```
var a: int32 = 1;
var b: int64 = 2;
var c := a + b;         // OK: a неявно расширяется до int64, тип c = int64
var d: float64 = a + b; // OK: int32→int64, затем int64→float64
var u: uint32 = 1;
var s: int32  = u + a;  // ОШИБКА: uint32 ↔ int32 неявно не приводятся
                        //   (нужно: int32(u) + a или u + uint32(a))
```

| Оператор | Описание           |
|----------|--------------------|
| `+`      | сложение           |
| `-`      | вычитание          |
| `*`      | умножение          |
| `/`      | деление            |
| `%`      | остаток от деления |

Деление целых чисел производит целое число (усечение к нулю):
`7 / 2 == 3`, `-7 / 2 == -3`.

Оператор `%` определён только для целых типов.

### 7.2 Логические операции

Применимы только к типу `bool`.
`&&` и `||` используют **короткое вычисление** (short-circuit evaluation):

- `false && expr` — правый операнд **не вычисляется**.
- `true  || expr` — правый операнд **не вычисляется**.

### 7.3 Операции сравнения

Возвращают `bool`. Применимы к:

- числовым типам — все операторы (`<`, `>`, `<=`, `>=`, `==`, `!=`)
- `bool` — только `==`, `!=`
- `string` — только `==`, `!=`

Если операнды числовые, но разных типов, к ним применяется то же
неявное widening, что и для арифметики (§7.1). Если widening невозможен —
**ошибка компиляции**, требуется явный cast.

Сравнение значений несовместимых типов (например, `string` и `int32`)
является **ошибкой компиляции**.

### 7.4 Строковые операции

| Операция          | Синтаксис       | Описание                    |
|-------------------|-----------------|-----------------------------|
| Конкатенация      | `s1 + s2`       | создаёт новую строку        |
| Длина             | `len(s)`        | встроенная функция → `int32`|
| Равенство         | `s1 == s2`      | сравнение по содержимому    |
| Неравенство       | `s1 != s2`      | сравнение по содержимому    |

Строки реализованы в кодировке UTF-8. `len` возвращает число **байт**, а не символов.

### 7.5 Унарные операции

| Оператор | Применимость       | Описание               |
|----------|--------------------|------------------------|
| `-`      | числовые типы      | арифметическое отрицание |
| `!`      | `bool`             | логическое отрицание   |

### 7.6 Индексирование массива

```
arr[i]
```

- `arr` должен быть типа `[T; N]`
- `i` должен быть целочисленным типом
- Результат имеет тип `T`
- Если `i < 0` или `i >= N` — **ошибка времени выполнения** (runtime error)

### 7.7 Доступ к полю структуры

```
expr.field
```

- `expr` должен иметь тип `struct`
- `field` должен быть объявлен в этом типе
- Результат — значение типа поля

### 7.8 Вызов функции

```
fn_name(arg1, arg2, ...)
```

- Функция должна быть объявлена **до** места вызова (forward declarations не поддерживаются)
- Число и типы аргументов должны совпадать с сигнатурой функции; к аргументам
  применяется неявное widening по правилам §6.2
- Возвращаемое значение имеет тип, указанный в объявлении функции
- Вызов функции с возвращаемым типом `void` не может использоваться как выражение

### 7.8.1 Вызов методов (impl)

См. grammar.md §3.2.5. Семантика:

**Инстанс-метод** — функция в `impl T`, у которой первый параметр объявлен как
`self: T`. Вызов:

```
obj.method(arg1, arg2, ...)
```

эквивалентен передаче `obj` в качестве `self`. Значение `obj` копируется
(call-by-value), модификации `self` внутри метода не видны вызывающему.

**Статический метод** — функция в `impl T` без параметра `self`. Вызов:

```
T.method(arg1, arg2, ...)
```

Разрешение метода производится по статическому типу `obj`/`T` в момент компиляции
(номинальная типизация). Имена методов разных типов не конфликтуют.

Если у типа `T` одновременно есть поле `m` и метод `m`, выражение `obj.m`
интерпретируется как поле; `obj.m(...)` — как вызов метода. Если возникает
неоднозначность, выдаётся ошибка компиляции.

### 7.9 Доступ к пространству имён

```
Namespace.identifier
```

Разрешается в момент компиляции. `identifier` должен быть объявлен
в указанном пространстве имён.

## 8. Семантика инструкций

### 8.1 Блок

Блок `{ stmt* }` вводит новую область видимости.
Инструкции выполняются последовательно сверху вниз.

### 8.2 Ветвление `if / else`

```
if expr { ... } else { ... }
```

- `expr` должен иметь тип `bool` — **ошибка компиляции**, если тип иной
- Ветка `else` необязательна
- `else if` является синтаксическим сахаром для вложенного `if`

### 8.3 Цикл `while`

```
while expr { ... }
```

- `expr` должен иметь тип `bool`
- Тело выполняется, пока условие истинно
- `break` — немедленно завершает ближайший охватывающий цикл
- `continue` — переходит к следующей итерации ближайшего охватывающего цикла
- `break` и `continue` вне цикла — **ошибка компиляции**

### 8.4 Возврат из функции `return`

```
return expr;   // в функции с не-void типом возврата
return;        // в функции с void типом возврата
```

- Тип `expr` должен совпадать с типом возврата функции
- Каждая ветка выполнения функции с не-void типом возврата **обязана** завершаться
  `return` — иначе **ошибка компиляции**
- `return` с выражением в `void`-функции — **ошибка компиляции**

### 8.5 Нулевая инструкция

Одиночный `;` является допустимой инструкцией без эффекта.

## 9. Побочные эффекты

Функции могут иметь побочные эффекты: ввод/вывод (`print`, `input`),
изменение переменных во внешних областях видимости. Язык не ограничивает
побочные эффекты и не вводит специальной системы их контроля.

---

## 10. Встроенные функции

### `print(v)`

Выводит значение `v` в стандартный поток вывода (stdout), после значения добавляется
символ перевода строки `\n`. Тип `v` может быть любым встроенным скалярным типом
или `string`. Вывод структур и массивов не поддерживается.

### `input() string`

Читает одну строку из стандартного потока ввода (stdin) до символа `\n`.
Символ перевода строки в возвращаемую строку не включается.

### `exit(code: int32)`

Немедленно завершает выполнение программы. Код `code` передаётся операционной системе
как код завершения процесса.

### `panic(msg: string)`

Аварийно завершает программу с выводом сообщения в stderr:

```
panic: <msg>
```

### `len(s: string) int32`

Возвращает длину строки в байтах.

---

## 11. Поведение при ошибках времени выполнения

При возникновении ошибки времени выполнения программа немедленно завершается
с выводом сообщения в stderr в формате:

```
runtime error: <сообщение> at line <N>
```

Обязательно обрабатываются:

| Ситуация                   | Сообщение                          |
|----------------------------|------------------------------------|
| Деление на ноль            | `division by zero`                 |
| Выход за границы массива   | `index out of bounds: N, size M`   |

Пример:
```
runtime error: index out of bounds: 5, size 3 at line 12
```

---

## 12. Функция `main` и код завершения

Программа обязана содержать функцию `main` с сигнатурой:

```
fn main() int32 { ... }
```

Значение, возвращённое из `main`, передаётся операционной системе
как код завершения процесса. `0` означает успешное завершение.

## 13. Модули

Каждый исходный файл является отдельным **модулем**. Программа состоит
из одного **корневого** модуля (передаётся в компилятор как точка входа)
и произвольного числа модулей, импортированных транзитивно.

### 13.1 Объявление модуля

Файл обязан начинаться с объявления:

```
module Name;
```

Правила:
- `module`-декларация должна быть **первым** ненулевым (после комментариев
  и пробелов) объявлением в файле. Иначе — **ошибка компиляции**.
- Имя `Name` обязано совпадать с именем файла без расширения `.herta`.
  Например, файл `Math.herta` обязан содержать `module Math;`.
- Имена модулей чувствительны к регистру.
- Только одно `module`-объявление на файл.

### 13.2 Импорт модулей

После `module` и до объявлений верхнего уровня могут идти импорты:

```
import Foo;
import Bar;
```

Правила:
- `import Name;` подгружает модуль `Name` (компилятор ищет файл `Name.herta`
  в каталоге **точки входа** программы).
- Допустим только импорт по имени модуля; импорт «отдельных символов»
  не поддерживается — доступ всегда квалифицированный `Name.x`.
- Циклический импорт (`A` импортирует `B`, `B` импортирует `A`) —
  **ошибка компиляции**.
- Повторный импорт одного и того же модуля в одном файле — **ошибка**.
- Самоимпорт (модуль импортирует сам себя) — **ошибка**.
- Если модуль `Name` не найден — **ошибка компиляции**.

### 13.3 Видимость (`pub`)

Каждое объявление верхнего уровня имеет один из двух уровней видимости:

| Объявление          | Видимость по умолчанию | С префиксом `pub`              |
|---------------------|------------------------|--------------------------------|
| `fn`, `struct`, `type`, `namespace` | приватное (виден только внутри модуля) | экспортируемое   |
| Поля `struct`       | публичны вместе со структурой | (отдельной разметки нет)    |
| Методы в `impl`     | приватные              | `pub fn ...` — экспортируется  |

«Приватный» означает «не доступен через `Module.X` извне». Внутри своего
модуля приватные объявления видны без ограничений.

```
module Math;

pub fn add(a: int32, b: int32) int32 { return a + b; }
fn double(x: int32) int32 { return x + x; }   // не экспортируется

pub struct Vec2 {
    x: float64,
    y: float64,
}

pub namespace Util {
    pub fn neg(x: int32) int32 { return -x; }
}
```

```
module Main;
import Math;

fn main() int32 {
    let v: Math.Vec2 = Math.Vec2 { x: 1.0, y: 2.0 };  // OK
    let n: int32 = Math.Util.neg(5);                   // OK
    let d: int32 = Math.double(3);   // ОШИБКА: double не помечен pub
    return Math.add(1, 2);
}
```

### 13.4 Разрешение имён через границы модулей

- Внутри файла действует обычное лексическое разрешение имён.
- К имени из другого модуля можно обратиться **только** в форме
  `Module.identifier` (или цепочкой — `Module.Namespace.identifier`).
- В качестве `Module` допустимо имя, **импортированное** в текущий файл.
- Имена импортированных модулей занимают то же пространство имён, что и
  локальные идентификаторы: запрещено объявлять переменную/функцию/тип
  с именем, совпадающим с именем импортированного модуля.
- Типы из разных модулей всё ещё **номинально** различны: даже если
  `Math.Vec2` и `Geom.Vec2` имеют идентичные поля, они несовместимы.

### 13.5 Точка входа

Функция `main` обязана быть объявлена в **корневом** модуле (том, что
передан компилятору первым аргументом). `main` не требует префикса `pub`.

## 13.1 Методы структур (impl)

Блок `impl T` группирует функции, ассоциированные с типом `T`.

Правила:
- `T` должен быть объявлен ранее как `struct` (или `type alias` на `struct`).
- Несколько `impl T`-блоков для одного типа допускаются, но имена методов
  не должны конфликтовать (в том числе между статическими и инстанс-методами).
- Метод считается **инстанс-методом**, если его первый параметр имеет имя `self`
  и тип, совпадающий с `T` (после раскрытия type alias). Все остальные методы —
  **статические**.
- Внутри тела метода `self` — обычная переменная-параметр, передаётся по значению.
  Мутирование `self` (через `self.field = ...`) допускается, если первый параметр
  объявлен как `var`-параметр (см. §3 о мутабельности; на данный момент параметры
  всех функций иммутабельны — мутирование `self` потребует возврата нового
  значения).
- Видимость методов: `obj.method(...)` доступен везде, где доступен тип `T`.
- Методы и обычные функции живут в **разных пространствах имён**: функция `f`
  и метод `T.f` не конфликтуют.

```
struct Counter { value: int32, }

impl Counter {
    fn make() Counter {
        return Counter { value: 0 };
    }
    fn get(self: Counter) int32 {
        return self.value;
    }
}

fn main() int32 {
    let c: Counter = Counter.make();
    return c.get();
}
```

## 14. Пространства имён

Пространство имён (`namespace`) группирует объявления верхнего уровня
под общим префиксом **внутри одного модуля**.

- Пространства имён могут содержать: функции, структуры, синонимы типов, `impl`-блоки.
- Вложенные пространства имён не поддерживаются.
- Доступ к элементу внутри своего модуля: `Namespace.identifier`.
- Доступ извне (после импорта модуля `M`): `M.Namespace.identifier`.
- Имена внутри пространства имён не конфликтуют с именами в глобальной
  области своего модуля.
- Префикс `pub` применим к самому `namespace` и **независимо** к его членам:
  внешняя видимость `M.N.x` требует, чтобы и `N`, и `x` были `pub`.

```
namespace Geo {
    type Coord = float64;

    fn distance(x: Coord, y: Coord) Coord {
        // ...
        return x;
    }
}

fn main() int32 {
    let d := Geo.distance(1.0, 2.0);
    return 0;
}
```
